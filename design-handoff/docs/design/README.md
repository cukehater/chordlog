# 코드집 — UI 구현 사양

기타 코드 악보 아카이브(1인용)의 화면 정본. **작업 전에 이 문서와 `tokens.css`를 먼저 읽으세요.**
`artboards/`의 `.dc.html`은 디자인 캔버스 전용 포맷입니다 — 수치를 읽어가는 용도이지, 그대로 복사해 쓰는 코드가 아닙니다.

---

## 1. 디자인 방향 한 줄

어두운 연습실. 바탕은 잉크(#0C0D10), 액센트는 앰버(#FF9D4D) **하나뿐**.
앰버가 칠해진 것은 언제나 "지금 연주할 것" — 코드 토큰, 현재 키, 카포 바, 강세, 주요 버튼. 그 외에는 쓰지 않습니다.

**타이포 3역할** (이 구분이 무너지면 디자인이 무너집니다):

| 역할 | 폰트 | 쓰는 곳 |
| --- | --- | --- |
| 디스플레이 | Hahmlet (serif) | 곡 제목 **전용**. 목록 행 제목, 상세 h1, 에디터 제목 입력 |
| 본문·UI | Gothic A1 | 문장, 라벨, 버튼, 가사 |
| 모노 | JetBrains Mono | 코드·키·BPM·프렛·TAB·마이크로 라벨 등 **모든 수치** |

마이크로 라벨(`KEY`, `CAPO`, `TUNING`, `PATTERN A`)은 모노 10px / `letter-spacing: .16em` / 대문자 / `--gc-text-dim`. 이 조합이 화면 전체의 리듬을 잡습니다.

**하지 말 것**: 그라데이션 배경(로그인 화면의 옅은 방사형 하나가 유일한 예외), 이모지, 아이콘 대신 이모지, 액센트 색 추가, 카드마다 좌측 컬러 바.

## 3. 화면별 사양

### 3.1 곡 목록 `/`

- 헤더 60px, 좌우 여백 48px, 하단 `--gc-line-hair` 1px. 좌: 16px 앰버 사각형 + "코드집"(Hahmlet 17/700), 우: 검색(280px) · 테마 버튼 · `새 곡`(앰버 배경 + `--gc-accent-ink` 글자).
- 히어로 `이어서 연습` 카드: 가장 최근 수정 곡. `CONTINUE PRACTICE` 라벨 → 제목(Hahmlet 30) → 아티스트·상태. 우측에 원키 / 튜닝 6현 토큰 / 카포 프렛보드 / `연주 시작` 버튼을 세로 구분선으로 나눠 배치.
- 곡 목록은 **카드 그리드가 아니라 트랙리스트**입니다. 행 높이 62px, 그리드 컬럼:
  `36px | minmax(0,1fr) | 64px | 92px | 104px | 84px` = 번호 / 제목+아티스트 / 키 / 카포 / 상태 / 수정일. gap 16px.
- 행의 제목은 Hahmlet 17/600, 아티스트는 13px `--gc-text-4`. TAB이 있는 곡·비표준 튜닝 곡은 아티스트 뒤에 모노 9px 배지(`TAB`, `DROP D`).
- 상태는 점 + 텍스트: 연습중 앰버 / 완성 `--gc-done` / 보관 `--gc-archived`.
- 모바일: 같은 트랙리스트를 행 68px로, 키 배지는 우측 끝 30px 고정. 우하단 56px 앰버 FAB(`--gc-r-dock`).

### 3.2 곡 상세 · 연주 뷰 `/songs/[slug]` — **가장 중요한 화면**

좌측 레일 352px + 우측 본문의 2단 구성.

**좌측 레일** (위에서부터): `← ALL SONGS` / 상태·태그 칩 / 제목(Hahmlet 36) / 아티스트 / 구분선 / **KEY**(원키 → 현재 키, 현재 키는 앰버 32px 모노) / **TUNING**(28px 토큰 6개 + 아래 6~1 줄번호, 변경된 줄만 앰버) / **CAPO 카드**(프렛보드 SVG + "N프렛" + 한 줄 설명) / TEMPO·UPDATED / 하단 고정 PRACTICE NOTE + 원본 영상 링크.

**컨트롤 바 — 2단 구조** (`--gc-surface-2`, `--gc-r-lg`, 가운데 1px 구분선):

- 1단 `KEY` — 키 ∓ 스테퍼, `RESET`, 카포 칩(미니 프렛보드), 튜닝 칩, 글자 ∓, 1단/2단 세그먼트, 우측 끝 집중 모드.
- 2단 `PLAY` — 오토스크롤 토글 + 속도 스테퍼, 구분선, 메트로놈 토글 + 박자 점 4개 + BPM 스테퍼 + `TAP` + 음소거, 우측 끝 상태 안내 문구.

집중 모드를 켜면 헤더와 좌측 레일이 사라지고 컨트롤 바는 **남습니다**(연주 중에 필요하므로). 카포·튜닝 칩을 컨트롤 바에 둔 이유도 이것입니다.

**악보 시트**: `--gc-surface`, `--gc-r-xl`, padding 30/36. 기본 2단(`column-count`), 섹션 라벨은 모노 대문자 + 우측으로 뻗는 헤어라인. 블록 종류는 `label` / `line` / `comment` / `tab` 네 가지(§4).

### 3.3 작성·편집 `/songs/new`

- 메타 영역은 **밑줄 입력**(테두리 없음, 하단 1px `--gc-line-strong`). 12컬럼 그리드:
  1행 `TITLE 4 · ARTIST 2 · KEY 1 · TEMPO 1 · STATUS 2 · REFERENCE 2`, 2행 `TUNING 3 · CAPO 5 · TAGS 4`.
- TUNING·CAPO·TAGS만 박스 카드(`--gc-surface-2` + `--gc-r-lg`)로 묶습니다. 카포는 드롭다운 + 프렛보드 미리보기 + "악보 코드는 바뀌지 않아요" 설명.
- 아래는 좌우 2분할: 왼쪽 소스(`--gc-surface-sunk`, 줄번호 거터 48px, 모노 12.5/24), 오른쪽 미리보기(`--gc-surface`).
- 소스 위에 삽입 툴바: `[코드] 섹션 스트러밍 TAB 6줄 메모`. **TAB 6줄을 손으로 치게 두지 마세요** — 이 버튼이 뼈대를 넣어줍니다.
- 파싱 오류: 해당 줄번호를 `--gc-danger`로, 하단에 `--gc-danger-bg` 스트립으로 `N행 · 이유`. 미리보기에서도 그 줄에 좌측 2px 빨간 바.
- 모바일은 `작성 | 미리보기` 탭 전환 + 같은 삽입 툴바(가로 스크롤).

### 3.4 로그인 `/login`

가운데 정렬, 헤더는 워드마크만. `ADMIN ACCESS` 라벨 → Hahmlet 52px 문구 → 설명 한 줄 → 밑줄 비밀번호 입력(모노 20px) → 로그인 유지 체크 → 앰버 버튼. 상단에 옅은 방사형 글로우 1겹(이 화면에만).

## 4. 공통 컴포넌트

### 4.1 코드-가사 정렬 (핵심 로직)

한 줄 = `{chord, text}` 쌍의 배열. 각 쌍은 세로 flex 박스 하나, 줄은 `flex-wrap: wrap`.
코드 span은 `min-height: 1.5em`, 가사 span은 `white-space: pre`.
→ 줄바꿈이 일어나도 코드가 가사에서 떨어지지 않고, 공백으로 정렬을 맞추지 않으므로 폰 화면에서도 안 깨집니다. `tokens.css`의 `.gc-pair` / `.gc-line` 참고.

글자 크기는 시트 컨테이너의 `font-size`만 바꾸고 내부는 전부 `em`으로 따라가게 하세요. 코드 0.76em, 섹션 라벨 0.62em, TAB 0.66em.

### 4.2 카포 프렛보드 (SVG, 표시 전용)

너트 + 프렛선 4개 + 현 5선 + N프렛 위치의 앰버 바. 크기 3종: 상세 레일 254×46(프렛 번호 포함), 컨트롤 바 44×18, 목록/모바일 34×16.
**카포는 코드에 아무 영향을 주지 않습니다.** 어디에 끼우는지만 알려주는 정보입니다.

### 4.3 스트러밍 그리드

16칸(16분음표). 칸당 25px(데스크톱) / 20px(모바일). 각 칸은 세로 3층: 라벨(`1 e & a`) / 화살표 / 강세 바.
- 박 칸(0,4,8,12): 라벨 `--gc-text-3` 700, 좌측에 1px 구분선.
- 다운 `↓` · 업 `↑` 18px `--gc-lyric`, 쉼 `·` 13px `#33373F`.
- 강세: 화살표를 앰버 700으로 + 아래 14×2px 앰버 바.
패턴마다 "어느 구간에서 쓰는지"를 제목 옆에 적습니다. 모바일은 A/B 토글로 하나씩.

### 4.4 TAB 블록

`--gc-bg` 배경 카드. 헤더에 `TAB` 라벨 + 제목 + 우측 반복 배지(`×3`). 본문은 6줄, 각 줄 = 줄 이름(`--gc-text-5`) + `|` + 내용(`--gc-tab`, `white-space: pre`) + `|`.
붙여넣은 아스키를 **그대로 보존**하는 것이 최우선입니다. 정렬을 재계산하지 마세요.

### 4.5 모바일 하단 독

`position: fixed`, 좌우 14px, 하단 24px, `--gc-surface-3` + `--gc-r-dock` + `--gc-shadow-dock`. 2단:
- 위: 오토스크롤 토글(46×44) · 속도 스테퍼 · 구분선 · 메트로놈 토글 · BPM 스테퍼
- 아래: 키 − [현재 키] + · 구분선 · 글자 ∓

메트로놈 버튼은 켜져 있을 때 **현재 박자 숫자(1·2·3·4)** 를 표시하고 첫 박에 앰버로 꽉 찹니다. 좁은 화면에서 박자 점을 따로 놓을 자리가 없어 버튼이 표시기를 겸합니다.

## 5. 상호작용 규칙 (그림만 봐서는 안 나오는 것들)

1. **이조**: 화면 상태만 바꾸고 `body`는 언제나 원키. `?key=+2`로 URL에 남겨 새로고침·링크 공유에서 유지.
2. **카포**: 표시 전용. 이조와 상호작용하지 않음.
3. **TAB·스트러밍은 이조 대상이 아님.** 키를 바꿔도 그대로 둡니다(프렛 숫자를 옮기면 카포·튜닝과 충돌).
4. **오토스크롤**: 켜면 자동으로 1단 보기로 전환(2단은 가로로 흐르는 레이아웃이라 세로 스크롤과 맞지 않음). 2단 버튼을 누르면 스크롤 정지. 끝에 닿으면 자동 정지. 속도 0.5×~3.0× 8단계, 1.0× = 25px/s. **배속만 보여주지 말고 px/s를 같이** 보여주세요.
5. **메트로놈**: 40~240 BPM, 곡의 `tempo`로 시작. 첫 박 강조(소리·시각 모두). 음소거해도 시각 박자는 계속. TAP 템포는 최근 간격 4개 평균.
   ⚠️ 시안은 `setInterval`이지만 **실제 구현은 Web Audio 스케줄러**(`ctx.currentTime` 기준 lookahead ~100ms)로 가세요. 탭이 백그라운드로 가면 `setInterval`은 박자가 흔들립니다.
6. **오토스크롤·메트로놈 상태는 URL·DB에 저장하지 않습니다.** 키와 달리 공유할 값이 아닙니다.
7. **집중 모드**: 헤더 + 좌측 레일만 숨김. 컨트롤 바는 유지.
8. 비로그인 방문자는 읽기 전용 — 편집/새 곡 버튼 자체를 렌더링하지 않습니다(비활성화가 아니라 미표시).

## 6. 접근성 (시안에서 이미 지킨 것들 — 유지하세요)

- 모바일 터치 타깃 최소 44px. 독 버튼 46×44, 아이콘 버튼 44×44.
- 아이콘만 있는 버튼에 `aria-label` 필수. 장식용 SVG는 `aria-hidden="true"`.
- `div` + `onClick` 금지. 실제 `<button>`, `<a href>`, `<input>` + `<label>`을 쓰세요(시안도 전부 그렇게 그려져 있습니다).
- 가짜 상태바·가짜 키보드를 그리지 않습니다. 모바일 상단 52px는 실제 상태바 자리로 비워둡니다.
- 본문 대비 4.5:1 이상. `--gc-text-dim` 이하는 10px 라벨 등 장식 텍스트에만.

## 7. 주의: 시안의 데이터는 전부 가짜입니다

`새벽 두 시의 골목 / 무렵`을 비롯한 곡·아티스트·가사는 저작권 문제를 피하려고 지어낸 것입니다.
시드 데이터로 쓰지 말고, 실제 채보로 교체하세요. TAB과 스트러밍 패턴도 마찬가지입니다.
