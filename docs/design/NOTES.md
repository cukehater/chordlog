# 구현 중 발견한 디자인 정본 질문

- 카포 프렛보드의 카포 바 x좌표 규칙이 아트보드마다 다르다. 레일(254×46, x=94)과
  에디터(200×38, x=73)는 "N번 프렛선 바로 뒤"지만, 컨트롤 바 칩(44×18, x=8)과
  모바일 칩(34×16, x=6.5)은 그 규칙을 따르지 않는다. 구현은 레일·에디터 규칙으로
  통일했고 작은 칩은 아트보드 대비 수 px 이동한다. 정본 확인 필요.
- `tokens.css`에 없는 색이 아트보드에 있다: #1A1C22(헤더 경계), #262A33(칩 테두리),
  #5A606C(너트), #2F333C(현), #3A3E47(헤어라인), #33373F(쉼표 글리프), #0F1116(독 안쪽).
  `app/globals.css`의 "아트보드 실측값" 블록에 넣어 뒀다. 정본 편입 여부 확인 필요.
- 홈 화면 필터 칩(`FilterChips`)이 아트보드 실측값으로는 32/34px인데, README §6의
  "모바일 터치 타깃 최소 44px. 절대 줄이지 말 것"과 어긋난다. 정본 우선순위(tokens.css >
  README > chordpro-spec > artboards)에 따라 구현은 모바일만 44px로 올리고
  (`h-[44px] md:h-[32px]`) 데스크톱은 아트보드값 32px을 유지했다. 디자인 오너 확인 필요.
- 모바일 연주 뷰(`MobilePlayView`)의 A/B 패턴 토글 버튼이 아트보드 실측값으로는
  28×26px인데, README §6의 44px 터치 타깃 규칙과 어긋난다. 정본 우선순위에 따라
  구현은 44×44px(`w-11 h-11`)로 올렸다. 디자인 오너 확인 필요.
- 에디터 삽입 툴바(`InsertToolbar`)의 버튼이 아트보드 실측값으로는 28px인데, README §6의
  44px 터치 타깃 규칙과 어긋난다. 이 툴바는 `/songs/new`·`/songs/[slug]/edit`의 모바일
  "작성" 탭에서 그대로 노출된다. 정본 우선순위에 따라 구현은 모바일만 44px로 올리고
  (`h-[44px] md:h-[28px]`) 데스크톱은 아트보드값 28px을 유지했다. 디자인 오너 확인 필요.
- 세그먼트 토글(`Segmented`)의 버튼이 아트보드 실측값으로는 32px인데, README §6의 44px
  터치 타깃 규칙과 어긋난다. 이 컴포넌트는 에디터 화면의 모바일 "작성 | 미리보기" 탭
  전환에도 쓰인다. 정본 우선순위에 따라 구현은 모바일만 44px로 올리고
  (`h-[44px] md:h-[32px]`) 데스크톱(컨트롤 바 1단/2단)은 아트보드값 32px을 유지했다.
  디자인 오너 확인 필요.
- 에디터 모바일 헤더의 저장 버튼(`SongEditor`)이 아트보드 실측값으로는 36px(h-9)인데,
  같은 헤더의 취소 링크(44px)와 어긋나고 README §6의 44px 터치 타깃 규칙과도 어긋난다.
  정본 우선순위에 따라 구현은 모바일만 44px로 올렸다(`h-11 md:h-9`). 데스크톱 저장
  버튼(`SiteHeader`의 saveBar)은 별개 엘리먼트이며 아트보드값 34px을 유지했다.
- 에디터의 `MetaForm` 전체가 모바일에서 44px 터치 타깃 규칙에 못 미친다 — 언더라인
  입력(`h-[34px]`), 태그/카포/튜닝 셀렉트(`h-[38px]`), 태그 × 제거 버튼(~16px, 패딩
  없음)까지 전부 44px 미만이다. 다른 컴포넌트들과 달리 아트보드에 모바일 메타 레이아웃
  자체가 없어 이 항목은 기록만 하고 개별 수정하지 않았다. 디자인 오너가 모바일 메타
  레이아웃을 확정하면 그때 일괄 적용 필요.
- `--color-hairline`(#3A3E47)을 `--color-sunk`(#0A0B0E) 위에 올리면 대비 약 1.8:1로
  WCAG AA 4.5:1(텍스트)·3.0:1(비텍스트) 모두 미달이다. 소스 창 줄번호 거터
  (`SourcePane.tsx`)만 `text-dim`(약 3.0:1)으로 올렸다 — 오류 스트립이 "N행"이라
  말하는데 그 줄번호를 못 읽는 조합을 없애는 게 목적이다. 나머지 사용처는 고치지
  않았다: 삽입 툴바 범례(`InsertToolbar.tsx`의 INSERT 라벨·단축키 안내)와 튜닝
  줄번호(`TuningTokens.tsx`)는 여전히 `text-hairline`이다. `--color-faint`(약 2.4:1)도
  기능성 텍스트에 쓰인다 — 컨트롤 바 안내 문구(`ControlBar.tsx`), 모바일 연주 뷰
  안내 문구와 URL 힌트 줄(`MobilePlayView.tsx`, `SongDetailView.tsx`), TAB 비박 칸
  라벨(`StrumGrid.tsx`, `TabBlock.tsx`)이 그 예다. 각각 의도한 저대비 장식인지,
  아니면 `text-dim`으로 올려야 하는 기능성 텍스트인지 디자인 오너 확인 필요.
