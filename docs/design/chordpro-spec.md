# 악보 포맷 · 도메인 로직 사양

`songs.body`에 들어가는 텍스트 포맷과, 그것을 화면으로 만드는 규칙.
**이 문서의 규칙은 디자인이 아니라 동작입니다. 임의로 바꾸지 마세요.**

---

## 1. 저장 원칙

- 본문은 **ChordPro 계열 플레인 텍스트 한 덩어리**. 코드를 대괄호로 가사 안에 박아 넣습니다.
- `body`는 **언제나 원키 기준**. 이조·카포는 렌더링 시점의 계산이며 저장하지 않습니다.
- 공백으로 정렬을 맞추지 않습니다. 정렬은 렌더러가 `{chord, text}` 쌍으로 만듭니다.
- 서비스를 접어도 이 텍스트만 있으면 내용이 살아남는 것 — 이게 포맷 선택의 이유입니다.

---

## 2. 전체 예시

```
{title: 새벽 두 시의 골목}
{artist: 무렵}
{key: G}
{capo: 2}
{tuning: E A D G B E}
{tempo: 72}

{sos: Intro (첫 G 두 번), Verse 1, Pre-Chorus}
D - D - D U D - D - D - D U - -
>               >
{eos}

{sot: 메인 리프  x3}
E|-------------10------------|
B|--13-11----11----11----11--|
G|-------10----------10------|
D|---------------------------|
A|---------------------------|
E|---------------------------|
{eot}

{soc: Verse 1}
[G]가로등 하나 [Em]꺼지고 남은 자리
[Am]우린 아직 [D7]여기 앉아 있어
{eoc}

{comment: 간주 — Verse 코드 그대로 2번}
```

---

## 3. 토큰

| 토큰 | 의미 | 처리 |
| --- | --- | --- |
| `{title:}` `{artist:}` `{key:}` `{capo:}` `{tuning:}` `{tempo:}` | 메타 지시어 | 파싱 시 DB 컬럼으로 분리, 본문에 렌더링하지 않음 |
| `[Am7]` `[G/B]` | 코드 | 바로 다음 글자 위에 붙음 |
| `{soc: 이름}` / `{eoc}` | 구간 | 섹션 라벨 + 블록 |
| `{comment: …}` | 연주 메모 | 회색 보조 줄 (좌측 2px 선) |
| `{sos: 구간들}` / `{eos}` | 스트러밍 패턴 | §5 |
| `{sot: 제목  xN}` / `{eot}` | TAB | §6 |
| 빈 줄 | 문단 구분 | 줄간 여백 |
| `\[` | 대괄호 문자 | 이스케이프 |

**코드 토큰 문법**: `루트[퀄리티][텐션][/베이스]` — `G`, `Am7`, `Csus4`, `F#m7b5`, `G/B` 모두 유효.
파서는 **루트와 베이스만** 반음 단위로 다루고 나머지 문자열은 그대로 보존합니다. 모르는 표기가 들어와도 내용을 잃지 않는 것이 원칙입니다.

---

## 4. 파서 출력

한 곡 = 블록 배열. 블록 타입은 다섯 가지뿐입니다.

```ts
type Block =
  | { k: 'label';   label: string }
  | { k: 'line';    pairs: { chord: string | null; text: string }[] }
  | { k: 'comment'; text: string }
  | { k: 'strum';   use: string; slots: Slot[] }        // 16개 고정
  | { k: 'tab';     title: string; repeat: string; lines: string[] } // 6줄 고정

type Slot = { stroke: 'D' | 'U' | null; accent: boolean }
```

`line`의 `pairs`는 **가사 조각 끝의 공백을 보존**해야 합니다. 그 공백이 코드 간격을 만듭니다.

파서·트랜스포저·렌더러는 `lib/chordpro/` 아래에 **DB와 무관한 순수 함수**로 두고 단위 테스트를 붙이세요. 이 서비스의 핵심 로직이고, 나중에 다른 플랫폼으로 옮겨도 그대로 씁니다.

---

## 5. 스트러밍 패턴

```
{sos: Intro (첫 G 두 번), Verse 1, Pre-Chorus}
D - D - D U D - D - D - D U - -
>               >
{eos}
```

- `{sos:}` 뒤는 **이 패턴을 쓰는 구간 목록**(쉼표 구분). 화면에서 패턴 제목 옆에 그대로 표시됩니다.
- 첫 줄: 공백으로 구분된 **정확히 16개** 토큰. `D`=다운, `U`=업, `-`=쉼. (16분음표 한 마디)
- 둘째 줄(선택): 강세 줄. 위 줄의 토큰 위치에 `>`를 놓습니다. 열 위치로 매칭하므로 **첫 줄과 같은 간격**을 유지해야 합니다.
- 렌더링: 16칸 그리드. 위에 `1 e & a 2 e & a 3 e & a 4 e & a`, 가운데 `↓`/`↑`/`·`, 강세는 앰버 + 하단 바. 박 칸(1·2·3·4) 좌측에 구분선.
- 입력은 `D`/`U`/`>`로 받고 **표시만 화살표**로 합니다. 화살표를 직접 타이핑하게 만들지 마세요.
- 에디터 삽입 툴바의 `스트러밍` 버튼이 위 4줄 뼈대를 넣어줍니다.

향후 3/4·6/8 박자를 지원한다면 `{sos: … | 3/4}` 처럼 뒤에 붙이고 슬롯 수를 12로 바꾸는 방향을 권합니다.

## 6. TAB

```
{sot: 메인 리프  x3}
E|-------------10------------|
B|--13-11----11----11----11--|
G|-------10----------10------|
D|---------------------------|
A|---------------------------|
E|---------------------------|
{eot}
```

- `{sot:}` 뒤는 제목, 끝의 `xN`은 반복 횟수 → `×N` 배지로 표시.
- 본문은 **정확히 6줄**, 위에서부터 1번줄(high E) → 6번줄(low E). 줄 이름과 `|`는 파서가 떼어내고 렌더러가 다시 붙입니다.
- **붙여넣은 아스키를 그대로 보존합니다.** 정렬을 재계산하거나 대시 개수를 정규화하지 마세요.
- 6줄이 아니면 저장 시 경고 (막지는 말고 알려주기).
- 표시: 모노, 줄 이름은 `--gc-text-5`, 내용은 `--gc-tab`, `white-space: pre`.

## 7. 이조 (transpose)

```js
const SHARP = ['C','C#','D','D#','E','F','F#','G','G#','A','A#','B'];
const FLAT  = ['C','Db','D','Eb','E','F','Gb','G','Ab','A','Bb','B'];

// semi: -11 ~ +11
// 규칙: 올리는 방향(+)은 샤프, 내리는 방향(-)은 플랫으로 표기한다.
// 루트와 베이스만 이동하고 퀄리티/텐션 문자열은 그대로 둔다.
transpose('Am7', +2) === 'Bm7'
transpose('G/B', +2) === 'A/C#'
transpose('G/B', -2) === 'F/A'
```

- 이명동음 예외 처리(예: E# / Cb)는 v1에서 하지 않습니다. 대신 **변환 결과를 본문에 복사하는 버튼**을 둬서 손으로 고칠 수 있게 합니다.
- 상태는 URL 쿼리(`?key=+2`)에만. 저장하지 않습니다.
- 단위 테스트: 샘플 5곡 × 12키 전조가 모두 유효한 코드 토큰을 내는지.

**이조하지 않는 것**: TAB(프렛 숫자), 스트러밍 패턴, 카포 값. 타브까지 옮기려면 별도의 "프렛 ±N" 기능으로 분리하세요.

---

## 8. 카포

- `{capo: N}` (0~7)은 **어느 프렛에 끼우는지만** 기록합니다.
- 코드 표시에 영향을 주지 않습니다. 울림 키를 계산하거나 잡는 모양을 역산하지 않습니다.
- 화면에서는 프렛보드 그래픽 + "N프렛"으로만 보여줍니다.

---

## 9. 튜닝

- `{tuning: E A D G B E}` — 6번줄(low E)부터 1번줄 순서.
- DB: `songs.tuning TEXT DEFAULT 'E A D G B E'`.
- 에디터는 프리셋(표준 / Drop D / 반음 내림 / 오픈 G / 직접 입력)으로 받고, 표시는 6현 토큰. 표준과 다른 줄만 앰버로 강조합니다.
- 목록에서는 비표준일 때만 `DROP D` 같은 배지를 답니다.

---

## 10. 오류 처리

- 닫히지 않은 대괄호(`[Am7 가사`) → 그 줄은 **코드 없이 가사로만** 렌더링하고, 줄번호와 이유를 에디터에 보고합니다.
- 저장은 막지 않습니다. "고칠 수 있게 알려주되 작업을 멈추게 하지 않는다"가 원칙입니다.
- 미리보기에서도 해당 줄에 `--gc-danger` 좌측 바를 그려 어디인지 보이게 합니다.

---

## 11. DB 델타 (기존 기획서 대비)

```sql
ALTER TABLE songs ADD COLUMN tuning TEXT DEFAULT 'E A D G B E';
```

- 스트러밍·TAB은 `body` 안에 살기 때문에 별도 컬럼이 필요 없습니다.
- FTS5 인덱싱에서는 `{sot}`~`{eot}` 블록을 **제외**하는 편이 낫습니다. 대시와 숫자가 검색 품질을 떨어뜨립니다.
- 한글 부분 검색 때문에 `trigram` 토크나이저를 쓰는 기존 결정은 유지.
